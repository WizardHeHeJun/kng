# 状态流转验证

> 可调用技能：分析功能中的状态机，验证状态流转的完整性和安全性。

## 触发条件

当策划案描述了以下内容时调用此技能：
- 明确的状态变化（如"未开始→进行中→已完成"）
- 条件触发的状态切换（如"达到 Lv.10 解锁"）
- 可逆/不可逆操作（如"装备穿戴/卸下"、"角色删除"）
- 并发操作场景（如"多人同时操作同一资源"）
- 定时状态变更（如"活动到期自动关闭"）

## 输入

- 策划案中描述的状态定义和流转规则
- 状态变更的触发条件
- 并发操作的可能性描述

## 执行步骤

1. **提取状态集合**：列出功能涉及的所有状态
2. **绘制状态转移矩阵**：
   - 每两个状态之间是否存在合法转换
   - 每个转换的触发条件
   - 转换是否可逆
3. **验证非法转换**：
   - 跳过中间状态直接到达终态
   - 从终态返回非终态
   - 不满足条件时强制触发转换
4. **分析并发冲突**：
   - 两个操作同时触发状态变更
   - 重复提交同一操作
   - 幂等性保证
5. **分析定时状态变更**：
   - 定时器到期时的状态处理
   - 定时器与手动操作的竞争条件
6. **验证状态持久化**：
   - 重启/重登后状态是否恢复
   - 断线重连后状态是否一致
7. **生成测试点**：每个状态转换场景生成一个测试点

## 输出规范

每个状态流转场景输出一个测试点，格式：
- `id`: TP-ST-xxx（ST = State Transition）
- `type`: "state"
- `title`: 状态流转描述（如"任务从进行中到已完成的正常流转"）
- `priority`: P0（核心状态流转 + 并发）/ P1（非法转换拦截）/ P2（边缘状态恢复）
- `from_state`: 起始状态
- `to_state`: 目标状态
- `trigger`: 触发条件
- `expected`: 转换后的预期结果

## 质量检查

- [ ] 所有合法状态转换路径都有对应测试点
- [ ] 至少覆盖 2 个非法状态转换（应被拦截）
- [ ] 并发操作场景至少覆盖：双端同时操作、重复提交
- [ ] 验证了断线重连后的状态恢复
- [ ] 不可逆操作有二次确认验证
