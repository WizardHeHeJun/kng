# 优先级与风险评估

> 可调用技能：对已生成的测试点进行优先级分配和风险标注，确保测试资源合理分配。

## 触发条件

此技能在其他技能产出测试点后自动调用，用于：
- 校准所有测试点的优先级分配
- 识别和标注高风险场景
- 补充风险项和待确认问题
- 生成测试策略建议

## 输入

- 其他技能产出的测试点列表
- 项目知识库中的已知风险和历史 Bug 模式
- 策划案中标注的重点和难点

## 执行步骤

1. **优先级校准**：按以下规则重新评估每个测试点的优先级
   - **P0 标准**：核心商业路径、涉及支付/发奖/扣款、数据一致性风险、用户资产相关
   - **P1 标准**：主要业务流程、关键配置变更、状态流转核心路径
   - **P2 标准**：非核心路径、低风险展示逻辑、辅助功能
2. **风险识别**：从以下维度识别风险
   - **技术风险**：高并发、大数据量、复杂状态机、多系统交互
   - **业务风险**：资产损失、数据泄露、用户体验严重受损
   - **历史风险**：项目知识库中类似功能的已知问题
   - **变更风险**：与现有功能的交叉影响
3. **标注待确认项**：从策划案中提取
   - 描述模糊无法设计测试的内容
   - "待定"、"TBD"、"后续补充"的部分
   - 与其他文档矛盾的描述
4. **生成策略建议**：
   - P0 用例必须在提测前全部通过
   - 高风险项建议增加探索性测试时间
   - 跨系统集成测试的执行时机

## 输出规范

输出三部分内容：

### 优先级调整
对需要调整的测试点，说明原优先级和建议优先级及原因。

### 风险清单
- `level`: "high" / "medium" / "low"
- `item`: 风险项描述
- `reason`: 风险原因（必须具体，不能只写结论）
- `mitigation`: 建议的缓解措施

### 待确认清单
- 问题描述
- 影响的测试点 ID
- 建议的确认方式（找策划确认/找开发确认/查阅其他文档）

## 质量检查

- [ ] P0 用例占比不超过 30%（避免全标 P0）
- [ ] 每个风险项都有具体原因，不是纯结论
- [ ] 涉及资产/支付的功能至少标注 1 个高风险项
- [ ] 待确认项明确了影响范围和确认方式
