# 权限与安全测试

> 可调用技能：分析功能的权限控制和安全边界，生成权限和安全测试点。

## 触发条件

当策划案涉及以下内容时调用此技能：
- 角色/身份区分（如"管理员/普通用户/游客"）
- 资源归属（如"只能操作自己的数据"）
- 功能解锁条件（如"VIP 专属"、"等级 30 解锁"）
- 敏感操作（如"支付"、"删除"、"转账"）
- 数据可见性（如"只能看到本公会的数据"）

## 输入

- 策划案中描述的角色/权限体系
- 功能的访问控制规则
- 敏感数据和操作的定义

## 执行步骤

1. **识别角色矩阵**：列出所有角色和权限等级
2. **建立权限矩阵**：每个角色对每个功能/操作的权限（可操作/只读/不可见）
3. **验证垂直越权**：
   - 低权限角色尝试执行高权限操作
   - 普通用户访问管理员接口
   - 未登录用户访问需登录功能
4. **验证水平越权**：
   - 用户 A 操作用户 B 的数据
   - 修改请求参数中的用户 ID
   - 跨公会/跨服务器访问
5. **验证解锁条件**：
   - 不满足条件时是否正确拦截
   - 条件变化后权限是否实时更新（如 VIP 到期）
   - 条件边界值（刚好达到/差一点达到）
6. **敏感操作防护**：
   - 二次确认机制
   - 操作频率限制
   - 敏感数据脱敏展示
7. **生成测试点**：每个权限场景生成一个测试点

## 输出规范

每个权限场景输出一个测试点，格式：
- `id`: TP-PM-xxx（PM = Permission）
- `type`: "permission"
- `title`: 权限场景描述（如"普通用户尝试访问管理员功能"）
- `priority`: P0（越权漏洞 + 资产安全）/ P1（权限拦截 + 解锁条件）/ P2（展示权限控制）
- `role`: 测试使用的角色
- `action`: 尝试的操作
- `expected`: 预期的权限控制行为（拦截/提示/隐藏）

## 质量检查

- [ ] 每种角色至少有 1 个正向权限测试和 1 个越权测试
- [ ] 水平越权至少覆盖：修改 ID 参数、跨归属访问
- [ ] 敏感操作（支付/删除）有二次确认和频率限制验证
- [ ] 权限变更后（如 VIP 到期）的实时性验证
