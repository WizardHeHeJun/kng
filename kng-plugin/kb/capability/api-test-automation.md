# 接口自动化设计

> 可调用技能：为策划案涉及的服务端接口设计自动化测试方案和脚本规范。

## 触发条件

当策划案涉及以下内容时调用此技能：
- 客户端与服务端的数据交互（如"请求服务器获取奖励列表"）
- 明确的 API 或协议描述
- 服务端计算或校验逻辑（如"伤害由服务端计算"）
- 数据持久化操作（如"购买记录写入数据库"）
- 多端同步（如"数据在多端保持一致"）

## 输入

- 策划案中涉及的接口或服务端交互描述
- 已知的 API 协议或数据格式
- 项目的测试框架和目录约定

## 执行步骤

1. **识别接口清单**：从策划案中提取所有需要服务端参与的操作
2. **设计参数校验**：
   - 必填参数缺失
   - 参数类型错误（字符串传数字、数字传字符串）
   - 参数值越界（引用边界值设计技能的输出）
3. **设计权限校验**：
   - 未认证请求（无 token / 过期 token）
   - 无权限请求（401/403 预期）
4. **设计业务逻辑校验**：
   - 正常业务流程的接口调用序列
   - 接口返回值的业务字段断言（不仅断言状态码）
   - 数据一致性验证（请求前后的数据变化）
5. **设计幂等性校验**：
   - 相同请求重复提交的处理
   - 并发请求的处理
6. **设计容错校验**：
   - 依赖服务超时的处理
   - 服务降级响应的格式
7. **规划脚本结构**：
   - 目录组织：`tests/api/<domain>/`
   - 命名规范：`test_<feature>_<scenario>.py`
   - 数据驱动：参数化覆盖边界值

## 输出规范

输出两部分内容：

### 接口测试点
每个接口场景输出一个测试点，格式：
- `id`: TP-API-xxx
- `type`: "api"
- `title`: 接口测试描述（如"购买接口参数缺失返回 400"）
- `priority`: P0（核心接口 + 资产相关）/ P1（业务接口）/ P2（查询接口）
- `endpoint`: 接口路径或协议名
- `method`: 请求方法
- `assertion`: 断言内容（必须包含业务字段，不能仅断言状态码）

### 脚本规范建议
- 推荐的目录结构
- 断言规范（必须描述业务语义）
- 失败日志要求（包含请求参数和关键响应字段）

## 质量检查

- [ ] 每个接口至少覆盖：正常请求、参数缺失、权限校验
- [ ] 涉及资产变动的接口必须有幂等性测试
- [ ] 所有断言包含业务字段，不仅仅是 HTTP 状态码
- [ ] 标注了需要参数化覆盖边界值的接口
